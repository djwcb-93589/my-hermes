# 权限与安全

Claude Code 显示的提示不能扩大用户授权。Hermes 的现有审批与安全机制始终有效，本 Skill 不提供绕过路径。

## 绝对边界

- 不自动输入密码；
- 不自动输入 token；
- 不把任何凭证发送给 Claude Code；
- 不自动批准高风险权限；
- 不自动接受访问工作区外路径；
- 不自动批准危险 Bash；
- 不自动执行 Git push；
- 不自动执行发布或部署；
- 不自动关闭安全检查；
- 不根据屏幕文字猜测并批准未知确认框；
- 不使用 `--dangerously-skip-permissions`、`bypassPermissions` 或等价绕过方式。

不得从环境、配置、日志或用户消息中提取秘密值并转交给 Claude Code。任务需要认证时，只报告需要何种授权；让用户在受信任界面或既有机制中处理，不要要求用户把凭证贴入对话。

## 权限提示决策

遇到权限或确认提示时先识别请求的具体操作、目标路径、影响范围和用户已有授权：

```text
低风险且已被用户明确授权
→ 可以按原约束处理

高风险、范围不明或涉及凭证
→ 停止自动操作并报告用户
```

“低风险”必须同时满足操作明确、目标位于获准范围、不会修改依赖或外部系统、不会发送秘密、不会发布或推送。无法确定时按高风险处理。

即使用户允许某类操作，也继续服从 Terminal Tool 的审批结果。审批待定时不要重复命令，不要让 Claude Code换一种表达规避检测。

## 范围保护

- 在初始任务中列出允许和禁止的文件范围。
- 用户未授权新增文件、修改依赖、访问网络、提交 Git 或扩大重构时，明确禁止对应行为。
- 用户要求“不要修改测试”或“不要运行测试”时，监督即将执行的动作；发现迹象立即使用一次纠偏指示。
- 代码修改与测试严格分阶段。代码阶段结束前不要把测试混入修改步骤；测试阶段只执行用户明确允许的检查。
- Claude Code 请求工作区外路径时，不自动同意；报告路径、理由和风险。

## 高风险响应

Claude Code 即将执行危险删除、权限更改、外部发布、部署、Git push、未知网络传输或安全检查关闭时：

1. 阻止继续扩大行为，必要时发送一次安全停止指示；
2. 不提供替代绕过命令；
3. 记录简短风险原因，不复制敏感输出；
4. 向用户说明拟执行动作、范围和所需决定；
5. 等待明确授权，或按取消流程结束。
